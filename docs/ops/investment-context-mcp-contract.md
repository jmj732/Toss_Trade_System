# Investment context MCP contract audit

**Audit date:** 2026-10-08
**Scope:** implemented read and version-checked proposal contracts. Local implementation does not imply production deployment or availability in a scheduled task session.

## Read contract

The authenticated context is a read model. `GET /investment/context` returns `ContextView`: portfolio, securities, watchlist, risk policy, decision ledger, pipeline, tactical portfolio overlay, and decision overlays. Tactical output is additive and has compatibility constructors for earlier `ContextView` and `SecurityView` callers. Source: [`InvestmentContextController`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextController.java#L23), [`ContextView` and view records](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L3476).

The implemented MCP tool is `get_investment_context`, served over `POST /api/v1/connector/mcp` and listed for `connector:read` (the trade scope also includes read tools). Its arguments may be empty or contain only `ticker` (1–32 letters, digits, `.`, `_`, or `-`). A ticker filters only `securities`; the other context fields remain the full authenticated user's view. An unknown ticker or unsupported argument returns `INVALID_ARGUMENT`; an absent context service or database access failure returns retryable `INVESTMENT_CONTEXT_UNAVAILABLE`; an unexpected failure returns `INTERNAL_ERROR`. Partial data and missing fields still return successful content (`isError=false`) with their native nulls and statuses. Successful calls return the `InvestmentContextService` DTO in structured content and text. The connector authentication identity supplies the user; the protocol calls `InvestmentContextService.context(userId)` and does not fetch Sheets, refresh a broker/provider, or write data. Source: [`MCP endpoint`](../../trading-backend/src/main/java/com/jmj/trade/connector/ConnectorMcpController.java#L22), [`tool declaration and read-only annotations`](../../trading-backend/src/main/java/com/jmj/trade/connector/ConnectorMcpProtocol.java#L144), [`tool argument schema and dispatch`](../../trading-backend/src/main/java/com/jmj/trade/connector/ConnectorMcpProtocol.java#L270), [`connector read scope`](../../trading-backend/src/main/java/com/jmj/trade/connector/ConnectorMcpOAuthService.java#L26), [protocol tests](../../trading-backend/src/test/java/com/jmj/trade/connector/ConnectorMcpProtocolTest.java#L218). Setup and transport details are in the [connector runbook](connector-runbook.md).

`risk.top2CorrelatedStatus` is evaluated only after portfolio, price, thesis-trigger, and per-position loss inputs pass their existing gates. Fewer than two held positions or enough paired daily returns with no positive correlation is `NOT_APPLICABLE`; fewer than 30 paired returns for any candidate pair without a positive qualifying pair is `INSUFFICIENT_HISTORY`; a mathematically undefined correlation with sufficient history and no positive qualifying pair is `UNVERIFIED`. A positive pair retains the existing `OK` or `STALE` input status. [`top2Correlated`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L3153).

`price.status` is the status of the selected latest quote (`latestPrice`). A quote with a classified session (`PREMARKET`, `LIVE_REGULAR`, `AFTER_HOURS`) uses the quote freshness window (default `PT15M`); the persisted-close fallback quote (`session=REGULAR_CLOSE`) keeps the regular-close maximum age (default `P7D`). A quote with `session=null` is never made `STALE` by the quote window alone: when `sessionReason=TOSS_QUOTE_OUTSIDE_DECLARED_INTERVALS`, it keeps its captured status (`PARTIAL`) until `nextDeclaredIntervalStartsAt` (the next interval start declared by the official Toss calendar at capture time) and is `STALE` afterwards; without stored calendar facts (including legacy snapshots and `TOSS_SESSION_UNVERIFIED`) it is `UNVERIFIED` after `PT15M` and `STALE` only after `P7D`. `SOURCE_CONFLICT` and `DATA_MISSING` are never rewritten. The canonical regular close is judged separately. The only path where a close reaches `latestPrice`, `price.status`, or risk inputs is the existing persisted-close fallback: it is selected only when no quote is accepted, is labeled `session=REGULAR_CLOSE`, and uses the `P7D` window; because calendar facts are captured only for an accepted Toss quote, its `regularCloseStatus` reads `UNVERIFIED`. Otherwise the close never substitutes for the quote. `regularCloseSessionDate` is the New York trade date of the Toss daily bar label, `lastCompletedSessionDate` is the last completed regular session declared by the Toss calendar for the capture instant's New York date, and `regularCloseValidUntil` is the declared end of the next regular session. `regularCloseStatus` is `OK` when the two dates match and `regularCloseValidUntil` has not passed, `STALE` when the close is older or that instant has passed, `UNVERIFIED` when the calendar facts are unavailable or unbounded, and `DATA_MISSING` without a close. Calendar facts are captured only for an accepted Toss quote; the read path does not call the broker. After the close, a snapshot whose last capture was an after-hours quote therefore reads `price.status=STALE` with `regularCloseStatus=OK` until the next session ends. Daily technical inputs use regular-close observations and their separate freshness check. `regularCloseAsOf` is the provider trade-date label (00:00 New York), not the exact exchange close instant. [`assessPrices`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentDataCalculator.java#L26), [`price windows`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L110), [`calendar facts`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L1144), [`read-path price status`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L2390).

### Revision and tactical performance

- Revenue/EPS revision windows are 30 and 90 days. Each result carries `value`, `baselineAsOf`, `status`, and `reason`. It compares the current Alpha estimate only with the same source, horizon, and estimate type history. Missing current estimate is `DATA_MISSING`; absent historical baseline is `INSUFFICIENT_HISTORY`; a zero baseline is `UNVERIFIED` with `ZERO_BASELINE`; otherwise the result is percent change using the absolute baseline as denominator. [`revisions`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L2484), [`revision`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentDataCalculator.java#L91), [`RevisionResult`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentDataCalculator.java#L243).
- `currentR` uses an explicit fresh quote mark and its timestamp, not a daily-close fallback. The performance payload keeps `evaluationAsOf`, `barAsOf` (last completed daily bar), and `markAsOf` separate; they must not be read as the same observation time or as an execution instruction. Initial risk is entry price minus initial risk price; initial R is 1 for a valid entry. `realizedR` uses explicit exit rows. MAE/MFE are excursions measured in R from completed daily bars after entry (and before full exit when fully closed). Forward returns require a recorded entry bar and matured daily bars. Statuses remain per metric. [`Performance`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayCalculator.java#L394), [`currentR`/`realizedR`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayCalculator.java#L450), [timestamp fields](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayService.java#L484), [`MetricValue` and DTO records](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayCalculator.java#L681).
- `dailyRolling20Vwap` is a 20-daily-bar, volume-weighted typical-price calculation `(high + low + close) / 3`. Anchored VWAP uses daily bars from the explicitly supplied anchor date, inclusive. These are daily OHLCV metrics, not intraday or execution VWAP. [`calculateRollingVwap`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayCalculator.java#L118), [`calculateAnchoredVwaps`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayCalculator.java#L350).
- Theme/market output is an aggregate with status/reasons, expected/eligible member counts, source/input references, and named metric objects that each carry `value`, expected/eligible counts, status, and reasons. Metrics are `ThemeReturn20D`, `ThemeRS20_SPY`, `ThemeBreadthEMA21`, `ThemeBreadthEMA50`, `MedianRVOL`, `BreakoutCount`, `BreakoutSuccessRate3D`, `BreakoutSuccessRate5D`, `FailedBreakoutRate`, and `MedianPostBreakoutReturn5D`. Theme membership is effective-dated; the market universe is explicit tracked tickers. Breakout cohorts are filtered by mature endpoint, common as-of, recent trading-bar window, and historical membership on the breakout date. [`calculateTheme`/`calculateMarket`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayAggregationCalculator.java#L34), [metric/status construction](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayAggregationCalculator.java#L108).

## Append investment decision

`append_investment_decision` is listed only when the authenticated connector key has the existing `connector:trade` scope and the `InvestmentContextService` bean is available. It remains available when live order execution is disabled. The tool accepts exactly the existing `DecisionInput` fields: `decisionId` (UUID), `asOf` (ISO-8601 instant), `asset` (ticker), `action` (`ADD`, `HOLD`, `REDUCE`, `EXIT`, or `REPLACE`), `referencePrice` (positive number), `priceSession` (`REGULAR_CLOSE`, `LIVE_REGULAR`, `AFTER_HOURS`, or `PREMARKET`), `horizon` (1–80 characters), `alphaThesis`, `invalidation`, `nextReviewTrigger`, and `confidence` (0–1). Unknown, missing, mistyped, or unsupported fields return `INVALID_ARGUMENT`.

The tool maps those fields directly to `InvestmentContextService.DecisionInput` and calls the existing `recordDecision(userId, input)` method. It does not infer missing values or create investment judgments. The service normalizes the ticker/action/session, trims text, bounds numeric precision, rejects future `asOf`, and computes `riskPolicyCheck`; `createdAt` is supplied by the backend. Replaying the same normalized decision UUID and body returns the stored row with its original server fields. A conflicting body or UUID owned by another user returns the sanitized `DECISION_CONFLICT`. Missing trade scope returns `TRADE_SCOPE_REQUIRED`; malformed or service-invalid fields return `INVALID_ARGUMENT`; an invalid authenticated user returns `AUTHENTICATED_USER_INVALID`; a missing investment state returns `INVESTMENT_STATE_NOT_FOUND`; storage failure returns retryable `INVESTMENT_CONTEXT_UNAVAILABLE`. `get_investment_context` reads the resulting user-owned DB row in `decisionLedger`; the Sheet `Decision Ledger` is also generated from that DB table, so no direct Sheet write/import path is introduced. The tool never prepares or submits an order. Source: [`tool declaration/schema/dispatch`](../../trading-backend/src/main/java/com/jmj/trade/connector/ConnectorMcpProtocol.java#L151), [`decision service`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L1291), [`DB-backed Sheet projection`](../../trading-backend/src/main/java/com/jmj/trade/sheets/InvestmentOsResearchSheetSync.java#L301).

The seven current legacy rows in the Sheet are not valid inputs for this tool: their action is `REVIEW`, their identifiers are not UUIDs, their price-session labels are outside the supported set, and six rows lack a reference price. The MCP tool does not import or convert them. It creates no replacement rows unless a caller supplies every valid canonical field; no action, UUID, session, or price is inferred. The pre-existing scheduled DB-to-Sheet mirror continues to follow its own rules and is not invoked by this tool.

## Review records (V58)

A **decision** (`investment_decision_ledger`, `append_investment_decision`, `POST /investment/decisions`) is an investment action: one of `ADD`/`HOLD`/`REDUCE`/`EXIT`/`REPLACE`, a UUID `decisionId`, a positive `referencePrice`, a supported `priceSession`, a single asset, and a server-computed `riskPolicyCheck`. A **review record** (`investment_review_records`) is only an audit note that something was reviewed and what was observed. It never creates a decision, order, or thesis, and the decision API/MCP contract is unchanged.

Review record fields:

| Field | Contract |
| --- | --- |
| `source` | `USER_REST`, `CONNECTOR_MCP`, or `SHEET_LEGACY_IMPORT`. `CONNECTOR_MCP` iff actor is `CONNECTOR_MCP` (DB check). |
| `recordKey` | Caller idempotency key, 1–128 characters, stored verbatim (not trimmed), need not be a UUID. Unique per (user, source). |
| `scope`, `asset` | `SECURITY` requires a ticker (normalized uppercase); `PORTFOLIO` requires no asset (a non-blank asset is rejected, not dropped). |
| `asOf` | When the review was made; required, not in the future, stored at microsecond precision. |
| `rawAction` | Verbatim label (≤64), e.g. `REVIEW`. Never mapped to a decision action. |
| `outcome`, `rationale`, `nextReviewTrigger` | Optional free text (≤2000 / ≤5000 / ≤2000), trimmed, blank → null. |
| `referencePrice` | Optional; positive if present (scale 8). Never required. |
| `rawPriceSession` / `priceSession` | Raw label stored verbatim (≤64). `priceSession` is set only when the raw value, after trim/uppercase, is exactly `REGULAR_CLOSE`, `LIVE_REGULAR`, `AFTER_HOURS`, or `PREMARKET`; otherwise null (DB check). Aliases are never guessed. |
| `sourceAsOf` | Optional evidence as-of time, not in the future. |
| `rawPayload` | JSON object, ≤16 KiB serialized. REST: the request body verbatim, or the explicit `rawPayload` object when supplied; MCP: the tool arguments verbatim. Required for `SHEET_LEGACY_IMPORT`, where it must be the full original row keyed by the original column names. |
| `actorType`, `actorUserId`, `actorSessionId`, `recordedAt` | Server-supplied audit fields. |

Idempotency: a replay with the same (user, source, `recordKey`) whose normalized fields **and** stored `rawPayload` (jsonb equality) match returns the stored row unchanged, even from another session. Any difference, including a differently spelled resend of the same values, is a conflict (`INVESTMENT_REVIEW_CONFLICT` over REST, `REVIEW_CONFLICT` over MCP). Rows are append-only (update/delete rejected by trigger). Context exposes the newest 50 owner rows as additive `reviewLog`; the ticker filter of `get_investment_context` only narrows `securities`.

### Legacy Decision Ledger rows

The seven legacy `Decision Ledger` Sheet rows (action `REVIEW`, non-UUID ids, unsupported session labels, six without a reference price, some portfolio-level) are not imported. Their target is `POST /investment/reviews` with `source=SHEET_LEGACY_IMPORT`, `recordKey` = the original row identifier, and `rawPayload` = the full original row. That import is **pending user-provided raw rows**; no row content was read or converted, and no action, UUID, price, or session is inferred. Date-only legacy `As Of` values need an explicit user-chosen time convention before import. The Sheet sync leaves legacy Decision Ledger rows untouched: rows whose id is not in the DB are never rewritten, and review records are mirrored only to `Review Log`.

`append_investment_review` is listed only with `connector:trade` and the review service available (also when order execution is disabled). Arguments: `recordKey`, `asOf`, `scope` (required); `asset`, `rawAction`, `outcome`, `rationale`, `nextReviewTrigger`, `referencePrice`, `rawPriceSession`, `sourceAsOf` (optional, nullable). `source` and `rawPayload` are not accepted. Unknown or mistyped fields return `INVALID_ARGUMENT`; missing scope returns `TRADE_SCOPE_REQUIRED`; storage failure returns retryable `INVESTMENT_CONTEXT_UNAVAILABLE`. Sources: [V58](../../trading-backend/src/main/resources/db/migration/V58__create_investment_review_records.sql), [`InvestmentReviewService`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentReviewService.java), [`InvestmentReviewController`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentReviewController.java).

## Implemented proposal and confirmation boundary

`put_investment_thesis` reuses the existing connector `connector:trade` write scope. Read-only keys cannot write. The tool remains available when order execution is disabled; storing research does not submit an order. No new app permission or scope is introduced.

Arguments are `ticker`, `thesis` (the existing ThesisInput fields), and optional `expectedUpdatedAt`. Creation omits the expected timestamp. Updates require the exact DB timestamp obtained from Context. User-scoped writes serialize on the owning user row. A stale version or an existing `CONFIRMED` thesis returns `THESIS_STATE_CONFLICT` and preserves the row. Model-tool `CONFIRMED` returns `CONFIRMATION_REQUIRED`; confirmation uses the existing authenticated user thesis route. Other unsupported states/fields return `INVALID_ARGUMENT`.

The model tool persists only `AI_PROPOSED`, `UNVERIFIED`, or `INVALIDATION_UNDEFINED`, without translating them to legacy states. It generates neither thesis text nor price risk levels. It returns the saved DB row; later Context reads and the existing Sheet scheduler consume that row. Writing only Sheet canonical thesis cells is insufficient because the mirror replaces them from DB. The thesis row itself is still an upsert, but every thesis write (MCP proposal and authenticated REST) now appends one row to `investment_thesis_revisions` (V57) in the same transaction: per-ticker monotonic `revision`, previous/new `invalidationStatus`, previous/new `priceRiskTriggerPrice`, `thesis_snapshot` (the saved row), `actor_type` (`CONNECTOR_MCP` or `USER_SESSION`), `actor_user_id`, `actor_session_id` (REST only), optional `source_as_of` and `reason`, and server `recorded_at`. Revisions recorded before V57 do not exist; earlier history (including original Sheet `UpdatedAt`/actor) is not backfilled. Evidence documents are not stored, only `source_as_of` and free-text `reason`.

`securities[].sizingEligibility` is additive; `risk.sizingEligible` remains boolean for existing clients.

| Label | Deterministic condition |
| --- | --- |
| `YES` | Thesis is `CONFIRMED` and the existing risk eligibility predicate is true. |
| `CONDITIONAL` | Thesis is `CONFIRMED` but the predicate cannot be satisfied with current operational inputs, including missing/stale price, weight, or risk level. |
| `NO` | Thesis is absent or not `CONFIRMED`. |

`risk.eligibilityReasons` is an additive, last field of `RiskContributionView`: a deterministic, ordered list of codes explaining why a position is not sizing-eligible, empty exactly when `sizingEligible` is true. Older callers keep the prior constructor signature. Codes separately distinguish missing inputs, missing approval, and stale data: `THESIS_MISSING`, `INVALIDATION_NOT_CONFIRMED`, `INVALIDATION_PRICE_NOT_CONFIGURED`, `INVALIDATION_PRICE_BREACHED`, `PORTFOLIO_STALE`, `PORTFOLIO_PARTIAL`, `PORTFOLIO_UNAVAILABLE`, `PRICE_STALE`, `PRICE_MISSING`, `PRICE_SOURCE_CONFLICT`, `PRICE_UNVERIFIED`, `POSITION_WEIGHT_MISSING`, then the portfolio budget codes `RISK_BUDGET_NOT_CONFIGURED`, `RISK_BUDGET_UNEVALUATED`, `RISK_BUDGET_EXCEEDED`. `sizingEligible` additionally requires `softBudgetStatus = WITHIN_SOFT_BUDGET` (portfolio `thesisFailureStress` ≤ `softRiskBudget` with status `OK`). All applicable codes are emitted in that fixed order; an `AI_PROPOSED` thesis with no trigger reports both `INVALIDATION_NOT_CONFIRMED` and `INVALIDATION_PRICE_NOT_CONFIGURED`. This list is a computed-state explanation only and is not an actor/evidence audit history.

These labels do not generate actions or orders. Theme meaning, AVWAP anchors, entry setup, initial risk price, and confirmation remain external inputs. Existing authenticated tactical REST input routes remain available; this change does not expose them as MCP write tools. It does not add an intraday feed, create Calibration Log, change Notion prompt versions, or update scheduled-task configuration. Actual runtime tool availability and deployment must be checked separately.
