# Investment context MCP contract audit

**Audit date:** 2026-10-08
**Scope:** implemented read and version-checked proposal contracts. Local implementation does not imply production deployment or availability in a scheduled task session.

## Read contract

The authenticated context is a read model. `GET /investment/context` returns `ContextView`: portfolio, securities, watchlist, risk policy, decision ledger, pipeline, tactical portfolio overlay, and decision overlays. Tactical output is additive and has compatibility constructors for earlier `ContextView` and `SecurityView` callers. Source: [`InvestmentContextController`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextController.java#L23), [`ContextView` and view records](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L3476).

The implemented MCP tool is `get_investment_context`, served over `POST /api/v1/connector/mcp` and listed for `connector:read` (the trade scope also includes read tools). Its arguments may be empty or contain only `ticker` (1–32 letters, digits, `.`, `_`, or `-`). A ticker filters only `securities`; the other context fields remain the full authenticated user's view. An unknown ticker or unsupported argument returns `INVALID_ARGUMENT`; an absent context service or database access failure returns retryable `INVESTMENT_CONTEXT_UNAVAILABLE`; an unexpected failure returns `INTERNAL_ERROR`. Partial data and missing fields still return successful content (`isError=false`) with their native nulls and statuses. Successful calls return the `InvestmentContextService` DTO in structured content and text. The connector authentication identity supplies the user; the protocol calls `InvestmentContextService.context(userId)` and does not fetch Sheets, refresh a broker/provider, or write data. Source: [`MCP endpoint`](../../trading-backend/src/main/java/com/jmj/trade/connector/ConnectorMcpController.java#L22), [`tool declaration and read-only annotations`](../../trading-backend/src/main/java/com/jmj/trade/connector/ConnectorMcpProtocol.java#L144), [`tool argument schema and dispatch`](../../trading-backend/src/main/java/com/jmj/trade/connector/ConnectorMcpProtocol.java#L270), [`connector read scope`](../../trading-backend/src/main/java/com/jmj/trade/connector/ConnectorMcpOAuthService.java#L26), [protocol tests](../../trading-backend/src/test/java/com/jmj/trade/connector/ConnectorMcpProtocolTest.java#L218). Setup and transport details are in the [connector runbook](connector-runbook.md).

### DTO surface

| Context field | Actual shape and meaning |
| --- | --- |
| `portfolio` | Combined portfolio view, including source, account/manual source dates, accepted snapshot status, staleness, and whether risk numbers are available. It is reconstructed from the latest persisted snapshot; GET does not read Sheets. |
| `securities[]` | Per-ticker price, technical, fundamental, consensus, revision, valuation, readiness, thesis, risk, and `SecurityTacticalOverlayView`. Non-held tracked securities may have a security view without an invented position. |
| `decisionLedger[]` | User-authored decision records; each includes the saved risk-policy check. |
| `tacticalOverlay` | Portfolio-level market JSON and theme aggregates, with status, as-of, source, and source-as-of. |
| `decisionOverlays` | Map keyed by the exact decision UUID. Each overlay contains decision-specific setup, risk price, effect, provenance/version, and performance. Do not project the latest ticker overlay onto every historical decision. |
| `SecurityTacticalOverlayView` | `status`, `reason`, `themeId`, string `trendStage`, external `entrySetup`, `initialRiskPrice`, `overlayEffect`, source/as-of/version, indicator/event/cohort/anchor JSON, and performance JSON. `getDailyAvwaps()` is a compatibility alias for `anchoredVwaps`. |

Source: [`ContextView`, `SecurityView`, `TacticalOverlayPortfolioView`, and tactical view records](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L3476).

### Revision and tactical performance

- Revenue/EPS revision windows are 30 and 90 days. Each result carries `value`, `baselineAsOf`, `status`, and `reason`. It compares the current Alpha estimate only with the same source, horizon, and estimate type history. Missing current estimate is `DATA_MISSING`; absent historical baseline is `INSUFFICIENT_HISTORY`; a zero baseline is `UNVERIFIED` with `ZERO_BASELINE`; otherwise the result is percent change using the absolute baseline as denominator. [`revisions`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L2484), [`revision`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentDataCalculator.java#L91), [`RevisionResult`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentDataCalculator.java#L243).
- `currentR` uses an explicit fresh quote mark and its timestamp, not a daily-close fallback. The performance payload keeps `evaluationAsOf`, `barAsOf` (last completed daily bar), and `markAsOf` separate; they must not be read as the same observation time or as an execution instruction. Initial risk is entry price minus initial risk price; initial R is 1 for a valid entry. `realizedR` uses explicit exit rows. MAE/MFE are excursions measured in R from completed daily bars after entry (and before full exit when fully closed). Forward returns require a recorded entry bar and matured daily bars. Statuses remain per metric. [`Performance`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayCalculator.java#L394), [`currentR`/`realizedR`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayCalculator.java#L450), [timestamp fields](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayService.java#L484), [`MetricValue` and DTO records](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayCalculator.java#L681).
- `dailyRolling20Vwap` is a 20-daily-bar, volume-weighted typical-price calculation `(high + low + close) / 3`. Anchored VWAP uses daily bars from the explicitly supplied anchor date, inclusive. These are daily OHLCV metrics, not intraday or execution VWAP. [`calculateRollingVwap`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayCalculator.java#L118), [`calculateAnchoredVwaps`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayCalculator.java#L350).
- Theme/market output is an aggregate with status/reasons, expected/eligible member counts, source/input references, and named metric objects that each carry `value`, expected/eligible counts, status, and reasons. Metrics are `ThemeReturn20D`, `ThemeRS20_SPY`, `ThemeBreadthEMA21`, `ThemeBreadthEMA50`, `MedianRVOL`, `BreakoutCount`, `BreakoutSuccessRate3D`, `BreakoutSuccessRate5D`, `FailedBreakoutRate`, and `MedianPostBreakoutReturn5D`. Theme membership is effective-dated; the market universe is explicit tracked tickers. Breakout cohorts are filtered by mature endpoint, common as-of, recent trading-bar window, and historical membership on the breakout date. [`calculateTheme`/`calculateMarket`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayAggregationCalculator.java#L34), [metric/status construction](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayAggregationCalculator.java#L108).

### Sheet inputs versus overwritten mirrors

- **Account State import:** current headers are `Account`, `Ticker`, `Asset Type`, `Currency`, `Quantity`, `Avg Cost`, `Current Price`, `Market Value`, `Cash`, `Source`, `Confidence`, `Synced At`, `Price Source`, `Price Synced At`, `State` (legacy header shape also supported). `ACCOUNT_2` rows are human/external input, including source labels such as `USER_SCREENSHOT`; rows need unique holding/cash identities, valid currency/quantity, enabled MANUAL registry, and source/date metadata for fully verified status. [`ACCOUNT_HEADERS`](../../trading-backend/src/main/java/com/jmj/trade/sheets/InvestmentOsSheetModel.java#L32), [`manualAccountEnabled`/validation](../../trading-backend/src/main/java/com/jmj/trade/sheets/InvestmentOsSheetModel.java#L351).
- Toss sync replaces `ACCOUNT_1` holding/cash source rows. It preserves valid `ACCOUNT_2` rows. Quote refresh may overwrite **Current Price, Price Source, Price Synced At, Market Value** for matching held rows in either account; it does not refresh manual quantity, average cost, row source, or manual `Synced At`. [`run`](../../trading-backend/src/main/java/com/jmj/trade/sheets/InvestmentOsSheetSyncService.java#L277), [`refreshPrices`](../../trading-backend/src/main/java/com/jmj/trade/sheets/InvestmentOsSheetModel.java#L421).
- **Portfolio Aggregate** (exact current headers: `Ticker`, `Currency`, `Quantity`, `Combined Avg Cost`, `Market Value`, `Cash`, `Accounts Included`, `Source Coverage`, `Confidence`, `Synced At`) and **Portfolio Metrics** (`asOf`, `Scope`, `Total Value`, `Cash USD`, `Cash %`, `High-water Mark`, `Drawdown %`, `SPY Reference`, `QQQ Reference`, `Notes`, `Source Coverage`, `Synced At`) are derived and rewritten only when account/manual inputs and quote completeness allow it. The documented USD metric sums both accounts’ USD holdings plus USD cash; KRW cash is excluded without verified FX. [`headers`](../../trading-backend/src/main/java/com/jmj/trade/sheets/InvestmentOsSheetModel.java#L43), [`portfolioMetrics`](../../trading-backend/src/main/java/com/jmj/trade/sheets/InvestmentOsSheetModel.java#L484).
- **Account Registry** headers are `Account`, `Label`, `Sync Mode`, `Source`, `Default Confidence`, `Enabled`, `Last Sync`, `Notes`. The configured broker sync updates `Last Sync` for ACCOUNT_1; ACCOUNT_2's MANUAL configuration is a human-controlled input. **Orders**, **Order History**, and **Reconciliation Log** are separately broker/reconciliation managed. [`registry headers`](../../trading-backend/src/main/java/com/jmj/trade/sheets/InvestmentOsSheetModel.java#L52), [`read/write flow`](../../trading-backend/src/main/java/com/jmj/trade/sheets/InvestmentOsSheetSyncService.java#L438).
- Research mirror tabs are `Security Snapshot`, `Thesis State`, `Consensus History`, `Watchlist`, `Decision Ledger`, `Alpha State`, and `Risk Policy`. The sync writes their generated tables from DB/context at `A1`; `Security Snapshot` includes the current complete header set in its code definition, `Thesis State` has 14 managed fields, including computed `Sizing Eligible`, and `Decision Ledger` has the 13 decision fields plus `EntrySetup`, `InitialRiskPrice`, `OverlayEffect`. Compatible Thesis State extension columns are preserved: canonical cells update at the existing ticker row, and new tickers append after occupied rows. `Next Catalyst` and `Next Review` remain external cells. `Sizing Eligible` is now a managed projection; its old manual value is replaced by the computed three-state label. Existing extra Decision Ledger columns are preserved/appended. A header conflict on Thesis State or Decision Ledger skips that tab and reports a partial mirror; other validated tabs can still sync. ## Existing authenticated write routes and gaps

The controller accepts the authenticated `Principal` and supplies its user UUID to service methods. Existing routes are:

| Route | Current effect |
| --- | --- |
| `PUT /investment/securities/{ticker}/thesis` | Validates and upserts the user/ticker thesis row. Its status field accepts the seven DB values listed above. This authenticated user route remains the confirmation path; the model tool cannot confirm. |
| `POST /investment/decisions` | Inserts caller-supplied `decisionId`; a repeated identical ID/body returns the existing row, while a mismatched duplicate or another user's ID conflicts. This is the only reviewed idempotency key. |
| `GET /investment/tactical-overlay/inputs` | Lists this user's tactical input history. |
| `PUT /investment/securities/{ticker}/avwap-anchors` | Appends an anchor input version and refreshes derived snapshots. |
| `DELETE /investment/securities/{ticker}/avwap-anchors/{anchorId}?sourceAsOf=...` | Appends an inactive anchor tombstone. |
| `PUT /investment/tactical-overlay/themes` | Appends a theme input version and refreshes derived snapshots. |
| `DELETE /investment/tactical-overlay/themes/{themeId}?sourceAsOf=...` | Appends an inactive theme tombstone. |
| `PUT /investment/tactical-overlay/themes/{themeId}/members/{ticker}` | Appends an effective-dated membership version and refreshes derived snapshots. |
| `DELETE /investment/tactical-overlay/themes/{themeId}/members/{ticker}?effectiveDate=...&sourceAsOf=...` | Appends an inactive membership tombstone. |
| `PUT /investment/securities/{ticker}/performance-entries` | Appends an entry input version and refreshes derived snapshots. |
| `DELETE /investment/securities/{ticker}/performance-entries/{key}?sourceAsOf=...` | Appends an inactive performance-entry tombstone. |

The tactical routes take caller-supplied source/sourceAsOf and are user-scoped. No idempotency key is defined, so repeated PUTs append another version. Route declarations and parameter types are in [`InvestmentContextController`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextController.java#L63).

Routes: [`InvestmentContextController`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextController.java#L33); implementations: [`putThesis`/`recordDecision`](../../trading-backend/src/main/java/com/jmj/trade/investment/InvestmentContextService.java#L1212), [`tactical input writes`](../../trading-backend/src/main/java/com/jmj/trade/investment/tactical/TacticalOverlayService.java#L228). V55 records `user_id`, caller `source`, `source_as_of`, active/tombstone state, version, payload, created time, and append order. It does not record a distinct actor kind, AI proposal id, explicit reviewer/approver, or confirmation event. Thesis upsert stores `updated_at`, but no revision/actor history. Decision ledger stores owner and creation time but no separate user-confirmation record. These are gaps for AI-originated writes, not evidence that current authenticated user routes are unprotected.

## Implemented proposal and confirmation boundary

`put_investment_thesis` reuses the existing connector `connector:trade` write scope. Read-only keys cannot write. The tool remains available when order execution is disabled; storing research does not submit an order. No new app permission or scope is introduced.

Arguments are `ticker`, `thesis` (the existing ThesisInput fields), and optional `expectedUpdatedAt`. Creation omits the expected timestamp. Updates require the exact DB timestamp obtained from Context. User-scoped writes serialize on the owning user row. A stale version or an existing `CONFIRMED` thesis returns `THESIS_STATE_CONFLICT` and preserves the row. Model-tool `CONFIRMED` returns `CONFIRMATION_REQUIRED`; confirmation uses the existing authenticated user thesis route. Other unsupported states/fields return `INVALID_ARGUMENT`.

The model tool persists only `AI_PROPOSED`, `UNVERIFIED`, or `INVALIDATION_UNDEFINED`, without translating them to legacy states. It generates neither thesis text nor price risk levels. It returns the saved DB row; later Context reads and the existing Sheet scheduler consume that row. Writing only Sheet canonical thesis cells is insufficient because the mirror replaces them from DB. The proposal upsert is not an append-only proposal/audit ledger and does not add actor/evidence revision history. Do not claim such history exists.

`securities[].sizingEligibility` is additive; `risk.sizingEligible` remains boolean for existing clients.

| Label | Deterministic condition |
| --- | --- |
| `YES` | Thesis is `CONFIRMED` and the existing risk eligibility predicate is true. |
| `CONDITIONAL` | Thesis is `CONFIRMED` but the predicate cannot be satisfied with current operational inputs, including missing/stale price, weight, or risk level. |
| `NO` | Thesis is absent or not `CONFIRMED`. |

These labels do not generate actions or orders. Theme meaning, AVWAP anchors, entry setup, initial risk price, and confirmation remain external inputs. Existing authenticated tactical REST input routes remain available; this change does not expose them as MCP write tools. It does not add an intraday feed, create Calibration Log, change Notion prompt versions, or update scheduled-task configuration. Actual runtime tool availability and deployment must be checked separately.
