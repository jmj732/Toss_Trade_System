# 모듈 경계 아키텍처 테스트 delta

## 범위

- ArchUnit 테스트 의존을 추가하고 `com.jmj.trade` 패키지 경계를 테스트로 강제한다.
- SPEC:57 이 "Spring Modulith 대신 패키지 경계와 아키텍처 테스트로 모듈성을 지킨다" 고
  명시했으나 그 아키텍처 테스트가 0개다. 독립 모듈을 만들지 않은 결정의 전제가 비어 있다.
- 실거래 코드가 올라가기 전에 경계를 고정해 위반 누적을 막는 것이 목적이다.
- 프로덕션 코드 구조는 규칙을 통과시키기 위해 필요한 만큼만 고친다. 새 모듈을 만들거나
  패키지를 대규모로 재배치하지 않는다.

## 모듈명 매핑

SPEC:65-80 의 모듈명과 실제 패키지가 다르다. 규칙은 실제 패키지 기준으로 쓴다.

| SPEC 모듈 | 실제 패키지 |
|---|---|
| `identity` | `security` |
| `event` | `intelligence` |
| `performance` | `prediction` |
| `broker`, `account`, `analysis`, `risk`, `order`, `inbox` | 동명 |
| `portfolio`, `marketdata`, `proposal` | 아직 없음 (B1, E1 범위) |
| `audit`, `outbox` | 독립 패키지 없음. `order`·`notification` 안에 존재 |

- 독립 `audit`/`outbox` 패키지명은 필수가 아니다. **경계 강제가 필수다.**
- 아직 없는 모듈을 위한 규칙은 쓰지 않는다. 해당 모듈이 생길 때 규칙을 함께 추가한다.

## 규칙

1. **의존 방향** — SPEC:65-80 의 허용 의존 표를 존재하는 모듈에 한해 강제한다. 표에 없는
   모듈 간 의존은 위반이다.
2. **`analysis` → `order`, `broker` 금지** (SPEC:95).
3. **`intelligence` → `analysis` 애플리케이션 서비스 직접 호출 금지** (SPEC:96). 재분석은
   outbox 경유여야 한다.
4. **JPA entity 의 모듈 외부 노출 금지** (SPEC:101). `@Entity` 타입은 선언 패키지 밖에서
   참조되지 않는다. 모듈 간 공유는 공개 application service 와 불변 ID/DTO 로 제한한다.
5. **단일 인자 `findById` 금지** (SPEC:100). 사용자 소유 aggregate 조회는 `userId` 를 필수
   인자로 받는다. `JpaRepository` 상속으로 들어오는 `findById(ID)` 의 **호출**을 금지한다.

## 위반 처리

- 규칙을 통과시키려고 **규칙을 완화하지 않는다.** 위반은 프로덕션 코드를 고쳐 없앤다.
- 모듈 재설계 없이는 못 고치는 위반만 예외로 둘 수 있다. 예외는 다음을 모두 만족해야 한다.
  - 코드가 아니라 **명시적 목록**으로 선언하고, 목록에 없는 위반은 실패한다.
  - 목록의 각 항목에 사유와 해소 예정 항목(플랜 원장 ID)을 적는다.
  - **목록이 늘어나면 테스트가 실패한다.** 상한을 단언해 debt 가 조용히 자라지 못하게 한다.
- 예외를 쓴 경우 무엇을 왜 얼렸는지 보고한다.

## TDD와 검증

- 5개 규칙이 전부 테스트로 존재하고 현재 코드가 통과
- 규칙이 실제로 위반을 잡는지 확인 — 각 규칙이 빈 집합에 대해 무조건 통과하는
  형태(vacuous pass)가 아님을 보장할 것
- 예외 목록을 쓴 경우 상한 단언이 함께 존재
- backend `./mvnw clean verify`
