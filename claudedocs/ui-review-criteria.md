# UI/UX 검수 기준 — web-dashboard

이 문서는 **판정 가능한 기준**만 담는다. "예쁘다/아니다" 는 기준이 아니다. 각 항목은 pass/fail 이 갈리고, 대부분 기계가 판정한다.

기준선: `DESIGN.md` · 감사 결과: `claudedocs/ui-ux-audit.md`

---

## 0. 게이트 요약

| 게이트 | 명령 | 잡는 계층 | 통과 조건 |
|---|---|---|---|
| 토큰 lint | `npm run lint:css` | L1 | 위반 0 |
| 단위·계약 테스트 | `npm test` | L4, L7 | 전부 통과 |
| 빌드 | `npm run build` | — | 성공 |
| 상태 매트릭스 + 시각회귀 | `npm run e2e` | L2, L3, L4 | 전 조합 통과 |
| 접근성 | `npm run e2e` (a11y spec) | L6 | WCAG 2.2 AA violation **0** |
| 전체 | `npm run verify` | 전부 | 위 전부 |

`npm run verify` 가 통과하지 않는 변경은 머지 대상이 아니다.

## L1. 토큰 — 정답은 하나만 존재

**색**
- `:root` 토큰 정의 블록과 다크 스킴 오버라이드 밖에서 raw hex 사용 = **fail**.
- 채움용 색과 텍스트용 색을 구분한다. 채움용을 텍스트에 쓰면 fail.
  - 텍스트: `--text`, `--text-muted`, `--accent-text`, `--warning-text`, `--danger-text`
  - 채움: `--accent`, `--accent-strong`, `--warning`, `--danger`
- **이 구분이 대비 미달 12건 중 과반의 원인이었다.** `--warning`(#f59f00)을 텍스트로 쓰면 흰 배경에서 2.13:1 이다.

**간격**
- `padding` / `margin` / `gap` 에 raw px = **fail**. `--sp-1`(4) ~ `--sp-20`(80) 11단계만.
- 4px 배수가 아닌 값은 존재할 수 없다. tie 는 **내림**(정보 밀도 보존).

**타이포**
- `font-size` 는 `--fs-2xs` ~ `--fs-hero` 7단계만. weight 는 `--fw-bold`(700) / `--fw-black`(800) 2단계. line-height 3단계.
- `font-weight: 750` 같은 값 금지 — 비가변 폰트 환경에서 700 으로 라운딩돼 구분이 사라진다.
- 금액·수량·비중 렌더 셀렉터는 `font-variant-numeric: tabular-nums` 필수.

**모양**
- `border-radius` 는 `--r-sm`(8) / `--r-md`(12) / `--r-lg`(16) / `--r-pill`(999) 4단계만.
- shadow 는 `--shadow-card` / `--shadow-raised` / `--shadow-popover` 3단계만.

**중복 선언 금지**
- 같은 셀렉터를 파일 두 곳에서 선언하면 fail. 실제로 `.metric-value` 이중 선언이 총 평가금액을 **44px → 16px** 로 죽였고 `npm test` 는 이를 잡지 못했다.

## L2. 컴포넌트 — 같은 역할은 같은 모양

- 버튼 variant 는 primary / secondary / danger 고정. 그 외 조합 = fail.
- 모든 인터랙티브 요소는 **5상태 전부 정의**: default / hover / active / focus-visible / disabled. 하나라도 없으면 fail.
- 터치타깃 ≥ 44px. 텍스트만으로 만든 토글(`summary` 등)도 예외 없음.
- `disabled` 는 사유를 구분한다. "요청 진행 중"(`cursor: wait`)과 "조건 미충족"(`cursor: not-allowed`)을 같은 어포던스로 표현하면 fail.
- 배지는 단일 계열로 수렴한다. 역할이 같은데 값만 미세하게 다른 배지 계열이 둘 이상이면 fail.

## L3. 레이아웃

- 브레이크포인트는 **480 / 900 / 1280** 3구간. 그 외 매직넘버 금지.
- 검증 뷰포트: **360 / 768 / 1280 / 1440**.
- `document.documentElement.scrollWidth > window.innerWidth` = **fail**. 가로 스크롤은 `.table-wrap` 같은 전용 스크롤 컨테이너 **내부에서만** 발생해야 한다.
  - 그리드 컬럼은 `minmax(0, 1fr)` 로 선언한다. 암묵적 `auto` 컬럼이 오버플로의 근본 원인이었다(`/predictions` 360px 에서 **+857px**).
- `100vh` 금지 → `100dvh`. 모바일 동적 툴바에서 세로 오버플로가 난다.
- 팝오버를 `position: fixed` 로 띄울 때 containing block 을 확인한다. 부모의 `position: relative` 때문에 패널이 **토글 버튼 폭**(≈55px)으로 축소된 사례가 있다.

## L4. 상태 커버리지 — AI 생성 코드 최대 구멍

데이터를 다루는 모든 섹션은 아래 6상태를 **각각 구분 가능하게** 표현해야 한다.

| 상태 | 필수 표현 |
|---|---|
| loading | 진행 중임이 보이고, 진행 중 액션 버튼이 비활성 |
| empty | **실제로 조회했고 결과가 없다**는 것이 확실할 때만 |
| partial | 어느 섹션이 왜 빠졌는지. partial 인데 "최신" 배지를 띄우면 fail |
| stale | 기준 시각 + stale 판정 근거 |
| error | 무엇이 왜 실패했고 다음에 뭘 해야 하는지 + **재시도 수단** |
| unauthorized | 재로그인 유도 요소 존재 |

**절대 금지**
- **미로딩을 empty 로 단언하지 않는다.** `section?.data ?? []` → "데이터가 없습니다" 는 fail. 조회 자체를 안 했으면 그렇게 말해야 한다.
- **미지 상태값을 정상으로 폴백하지 않는다.** 화이트리스트에 없는 값은 `UNKNOWN` 으로 명시하고 원본 값을 보조 표기한다. `statusFrom` 이 미지 값을 전부 `READY` 로 폴백해 CANCELED·TIMEOUT 이 정상으로 보였다.
- **한 섹션 실패가 전체를 죽이지 않는다.** `Promise.all` 단일 catch = fail. `Promise.allSettled` + 섹션별 분리.
- **판정 미완료를 실패로 표기하지 않는다.** `directionCorrect == null` 을 `MISS` 로 렌더하면 모델 성과를 실제보다 나쁘게 오인시킨다.
- `undefined` / `null` / `NaN` / `[object Object]` / `Invalid Date` 가 화면에 보이면 **무조건 fail**. 자동 검사 대상.

## L5. 피드백·인터랙션

- 부작용 있는 액션은 **즉시 시각 반응 + 진행 중 잠금 + 성공/실패 명시**. 무반응 = fail.
- **중복 제출 가드**: 진행 상태를 스칼라로 두지 않는다. 두 대상을 동시 실행하면 먼저 끝난 쪽의 `finally` 가 진행 중인 다른 버튼을 재활성화한다. **Set 으로 관리**한다.
- **멱등키는 결정적이어야 한다.** 클릭마다 `crypto.randomUUID()` 를 새로 만들면 서버 중복 감지가 무력화된다. `대상 + 액션` 기준으로 생성해 재시도 간 재사용한다.
- 비활성화 조건은 요청 **시작 시점**에 세운다. 응답 이후에 세우면 진행 중에 버튼이 활성 상태로 남는다.
- 파괴적 액션은 확인 단계 필수.
- 폼 제출 실패 시 **입력값을 보존한다**. `await` 없이 `form.reset()` 하면 실패 시 데이터가 소실된다.
- 실패해도 **탈출구는 살아 있어야 한다.** 로그아웃이 서버 오류로 실패해도 로컬 세션은 비운다.
- 애니메이션 150~250ms, `prefers-reduced-motion` 대응 필수.

## L6. 접근성 — WCAG 2.2 AA, 기계 판정, 타협 없음

**게이트: axe violation 0.** 예외 없음.

- 대비: 텍스트 4.5:1, UI 컴포넌트·그래픽 3:1, **포커스 표시 3:1**(2.4.11).
  - 포커스 링에 알파 색상 금지. `outline: 0` 후 반투명 링으로 대체하면 1.24:1 이 된다. 불투명 2겹 링을 쓴다.
- 키보드만으로 전 플로우 완주. 포커스 항상 보임, 순서 = 시각 순서.
- `overflow-x: auto` 스크롤 영역에는 `tabindex="0"` + `role="region"` + `aria-label`. 없으면 키보드로 표의 오른쪽 열에 도달할 수 없다(2.1.1).
- 상태를 **색만으로** 전달 금지. 차트 선은 `stroke-dasharray` 등 형태 구분을 함께 준다.
- 비동기 갱신은 `role="status" aria-live="polite"` 로 고지한다.
- 오류는 `role="alert"`. 페이지당 `h1` 1개, 헤딩 레벨 스킵 금지, 모든 콘텐츠가 랜드마크 안에 있어야 한다.
- 현재 위치는 `aria-current="page"` 로 표시한다.
- `lang="ko"` 문서에 영어 `aria-label` 금지 — TTS 가 오독한다.

## L7. 콘텐츠 — 표기 규칙 단일화

전부 `lib/format.js` 를 경유한다. 컴포넌트에서 직접 포맷하면 fail.

| 대상 | 규칙 |
|---|---|
| 금액 | 통화 **접두**, 천단위 구분, KRW 0자리 / USD 2자리. **서버 승인 검증 자릿수와 일치**해야 한다 |
| 손익 | 통화 뒤에 부호 (`KRW +1,000` / `KRW -1,000`) |
| 비중·집중도 | 항상 % 환산. 원시 소수(0.3421)는 금액 열 옆에서 금액으로 오독된다 |
| 시각 | 단일 표시 타임존 고정 + **타임존 라벨 필수**. 원시 ISO 노출 금지 |
| 값 없음 | `UNKNOWN_TEXT`("확인 필요") 하나로 통일. "—" 와 혼용 금지 |
| 오류 | 코드→한국어 사전 경유. `INTERNAL_ERROR` 같은 영문 코드 노출 금지 |
| 내부 식별자 | 백엔드 필드 경로(`account.cashBalance`)·enum 원문(`KNOWN`/`UNKNOWN`) 노출 금지 |

## L8. 거래 화면 필수 기준 — 별도 게이트

일반 UI 기준과 **별도로** 적용한다. 여기서 fail 은 금전적 오판으로 이어진다.

1. **데이터 freshness**: 금액·지표에 기준 시각이 반드시 함께 표기된다. stale 이면 판정 근거를 보여준다.
2. **통화**: 금액에 통화 단위가 항상 붙는다. 통화 구분 없는 합산 금지.
3. **시간대**: 모든 시각에 타임존 명시. 입력이 로컬 시각이면 라벨에 명시한다. `datetime-local` → `toISOString()` 후 UTC 원문 표시는 **9시간 오차**를 만든다.
4. **주문 상태**: 상태값 종류와 화면 표현이 1:1 대응. 미지 상태는 `알 수 없는 상태: X` 로 노출한다. 승인 후 결과 상태를 확인할 경로가 있어야 한다.
5. **중복 제출**: L5 의 가드 규칙 + 서버 멱등성이 실제로 동작해야 한다. **e2e 여정에서 연타 시 POST 1회를 어서션한다.**
6. **UNKNOWN 표현**: 사용자가 이해할 수 있는 한국어. 원시 필드명·enum 노출 금지.
7. **승인 게이트 무결성** — 가장 중요
   - 서버가 "사용자가 본 값"을 검증한다면, 그 값은 **반드시 화면에 렌더된 뒤 사용자 확인을 거쳐** 전송되어야 한다.
   - 클라이언트가 preview 를 조회해 그대로 되돌려보내면 게이트는 무력화된다. 양쪽 모두 서버값이라 항상 통과한다.
   - **e2e 어서션**: POST body 의 `displayed*` 값이 패널에 실제 표시된 텍스트와 일치하는지 검증한다. 이것이 게이트다.

## 회귀 방지 원칙

**"테스트가 전부 통과했다"는 안전의 증거가 아니다.**

이 감사에서 실제로 있었던 일:
- 단위 테스트 107개가 전부 통과하는 상태에서 **주문 승인이 완전히 깨져 있었다**. `actOnProposal` 의 안전 게이트는 세워졌는데 호출부가 옛 방식이었고, 두 경계를 함께 검증하는 테스트가 없었다.
- `.metric-value` 중복 선언이 화면 최상위 지표를 16px 로 죽였지만 어떤 테스트도 잡지 못했다.

따라서:
1. 안전 게이트를 추가하면 **호출부까지 함께 검증하는 테스트**를 반드시 추가한다.
2. CSS 회귀는 단위 테스트로 잡히지 않는다 — 시각회귀 baseline 이 그 역할을 한다.
3. **망가진 화면을 baseline 으로 승인하지 않는다.** baseline 은 전 지표가 그린인 시점에만 생성한다.
4. 게이트가 실패하면 **원인을 고친다.** 임계값 완화·어서션 약화·테스트 스킵으로 통과시키지 않는다.
